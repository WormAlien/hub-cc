### [DEGRADED] Чтение payload держится на `read -t`, а на системном bash 3.2 макоси частичный ввод при таймауте не сохраняется
- **Где:** `routing/statusline-autoreger.sh:20-24`
  ```bash
  payload="${STATUSLINE_PAYLOAD:-}"
  if [ -z "$payload" ]; then
      IFS= read -r -d '' -t 2 payload 2>/dev/null || true
      payload="${payload:-}"
  fi
  ```
- **Что происходит на маке:** штатный путь (Claude Code пишет JSON и **закрывает** stdin) отрабатывает везде: `read -d ''` упирается в EOF, возвращает 1, но переменную присваивает — это поведение одинаково во всех bash. Проблема — во втором сценарии: если stdin остаётся открытым и `read` доходит до таймаута, **bash 4.0+ сохраняет прочитанный кусок в переменную, а bash 3.2 — нет**. macOS до сих пор поставляет `/bin/bash` 3.2.57 (перейти на 5.x мешает GPLv3), и если `bash` в PATH у Claude Code окажется системным, а не brew'шным, `payload` останется пустым → `model_id="unknown"`, контекстное окно не рисуется, баланс не рисуется.
- **Почему это не гипотеза на ровном месте:** ровно этот симптом на маке уже ловили — комментарий `:15-19` описывает, как `timeout 2 cat` молча давал пустую строку («поймано на живом маке 2026-08-20»), и `read -t` пришёл как лекарство. Лекарство верное, но его гарантия версионная, а версия на маке — минимальная из возможных.
  Какой именно `bash` возьмётся, решает PATH: `enable-statusline.js:45` пишет в настройки `bash "<путь к шиму>"` без абсолютного пути к интерпретатору, а шим `:43` делает `exec bash "$target"` — тоже по PATH. Есть Homebrew в PATH процесса Claude Code → bash 5, нет → `/bin/bash` 3.2.
- **Проверено локально:** на bash 5.3 обе ветки работают как задумано — при закрытом stdin переменная получает payload целиком, при таймауте остаётся пустой. Разницу 3.2 против 4.0 воспроизвести здесь нечем (в окружении только bash 5), отсюда PLAUSIBLE.
- **Фикс:** снять зависимость от версии, а не гадать. Достаточно не полагаться на сохранение частичного ввода:
  ```bash
  # 🪤 bash 3.2 (системный на macOS) при таймауте `read -t` НЕ сохраняет прочитанное.
  # Поэтому таймаут — только страховка от вечного блока, а данные берём по EOF.
  payload="${STATUSLINE_PAYLOAD:-}"
  if [ -z "$payload" ]; then
      IFS= read -r -d '' -t 2 payload 2>/dev/null || true
      payload="${payload:-}"
      # добор посимвольно, если версия bash съела частичный ввод
      if [ -z "$payload" ]; then
          while IFS= read -r -t 1 -n 4096 chunk 2>/dev/null; do payload="$payload$chunk"; done
          payload="$payload${chunk:-}"
      fi
  fi
  ```
  Проверка на маке (одна команда, отвечает на всё сразу):
  `bash -c 'echo $BASH_VERSION'` и `/bin/bash -c 'sleep 3 | { read -r -d "" -t 1 v; echo "[$v]"; }'`.
  Диагностика вживую уже встроена: `touch logs/.statusline-debug` (`:53-54`) — сырой payload начнёт копиться в `logs/.statusline-debug.jsonl`; пустые строки там = проблема подтвердилась.

### [DEGRADED] `*_KEEPALIVE_URL` и `ANTHROPIC_BASE_URL` пишутся через `localhost`, а слушатели биндятся только на `127.0.0.1`
- **Где:** `routing/transparent-proxy.js:7515, 7521, 12166, 12817, 12852, 14149, 14839, 15741, 16398, 17119, 18066` (`const XX_KEEPALIVE_URL = \`http://localhost:${PORT}\``) и `:4505` (`settings.env.ANTHROPIC_BASE_URL = \`http://localhost:${proxy.port}\``). Слушатели — `keepalive-proxy.js:2650`, `frontdoor-proxy.js:709`, `custom-openai-proxy.js:529`, `agentrouter-proxy.js:1016`: все `('127.0.0.1')`.
- **Что происходит на маке:** на маке `/etc/hosts` даёт `localhost` → и `127.0.0.1`, и `::1`, причём `getaddrinfo` обычно отдаёт `::1` первым. На Node 20+ спасает `autoSelectFamily` (по умолчанию `true` с v20.0.0) — соединение уйдёт в `::1`, получит мгновенный `ECONNREFUSED` и переиграет на IPv4. **На Node 18 `autoSelectFamily` по умолчанию `false`** — соединение уходит в `::1` и умирает, то есть Claude Code вообще не видит бэкенда.
- **Почему:** `install-mac.sh:154` пропускает всё, что `>= 18`: `if [ "$NODE_MAJOR" -lt 18 ]; then brew upgrade node; fi`. Ровно Node 18 проходит проверку и попадает в дырку. Ирония в том, что этот класс уже вылечен — но только во front-door: `frontdoor-proxy.js:88-97` (`connectHost()`) осознанно переписывает `localhost` → `127.0.0.1` с комментарием «`localhost` на Windows разрешается в ::1», и тест на это есть (`:636`). Дашборд, который эти URL порождает, той же дисциплины не соблюдает.
- **Фикс:** два шага, оба дешёвые.
  1. Заменить литерал в одиннадцати константах и в `:4505` на `127.0.0.1` — снимает проблему в корне (front-door всё равно нормализует, но `settings.json` читает и сам Claude Code).
  2. Поднять планку в `install-mac.sh:154` до `-lt 20`.
  Проверка на маке: `node -e "require('dns').lookup('localhost',{all:true,verbatim:true},(e,a)=>console.log(a))"` — если первым идёт `::1`, риск реален; `node -p "process.versions.node"` — если 18.x, оно уже сломано.
- **Уверенность:** PLAUSIBLE (порядок адресов зависит от конфигурации хоста; на Node ≥20 — только лишние ~0 мс, на Node 18 — отказ)
