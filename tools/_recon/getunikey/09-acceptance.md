### Пункт 5 — как проверяется `/model <префикс>` через front-door `:20100`

**Порт и вход.** `routing/frontdoor-proxy.js:37` — `const PORT = Number(process.env.PORT || 20100);`, слушает только `127.0.0.1` (`:936`, там же ассерт `:883`). Это **фиксированный** вход Claude Code (шапка `:1`, `:8`): base URL навсегда `http://127.0.0.1:20100`, выбор провайдера — не переездом порта, а **префиксом модели**. Дашборд-ручка, которую front-door дёргает для подъёма — `SWITCH_PORT` по умолчанию `8200` (`:117`).

**Скрипты в `tools/` — ВСЕ песочные, живой `:20100` не трогают** (важно: ни один нельзя принять за приёмку боя):
| Скрипт | Порт теста | Что проверяет |
|---|---|---|
| `tools/check-frontdoor.js` | `20191` (дашборд-песочница), `20192` (front-door-песочница) | чекпоинт `writeSettings→applyFrontdoor`, свой `USERPROFILE` в `%TEMP%` (канон: `29/29`) |
| `tools/check-frontdoor-ensure.js` | `21411` (FD), `21412` (поддельный дашборд), `21413` (апстрим), `21414` (мёртвый) | автоподъём keepalive по префиксу: запрос доезжает, апстрим ровно 1 раз, префикс срезан, дедуп пачки, отказ → 502 с причиной (канон: `10/10`) |
| `tools/check-frontdoor-abort.js` | `28311` (FD), `28312` (заглушка) | ловля ухода клиента (баг 25.08, `req.on('aborted')` на Node 17+) |
| `tools/check-routes-default.js` | `21421` (FD), `21422` (поддельный шлюз) | голое имя шлюза → `default` из `<prefix>-routes-modelmap.json`; живой `active-backend.json` остаётся |

⇒ Ни один не бьёт в боевой `:20100` и ни один не делает платных запросов (апстримы поддельные).

**Приёмка в бою — только руками, `curl`'ом** (канон — [[Роутинг по модели, а не по активному провайдеру]] § «Приёмка в бою», строки 242-254). Дословные команды:

```sh
# 1) проба маршрута (модель заведомо небывалая — «probe»): платных запросов НОЛЬ
curl -s -o /dev/null -w '%{http_code} %{time_total}\n' \
  -X POST http://127.0.0.1:20100/v1/messages \
  -H 'content-type: application/json' \
  -d '{"model":"uk/probe","max_tokens":1,"messages":[{"role":"user","content":"x"}]}'

# 2) состояние маршрутизации front-door
curl -s http://127.0.0.1:20100/__frontdoor/api/status

# 3) лайв-чек жив ли вход (шаг 8b doctor.sh)
curl -s --max-time 3 http://127.0.0.1:20100/__frontdoor/api/status
```

**Что считается успехом:**
- `POST :20100 {"model":"<prefix>/probe"}` → **код от самого шлюза** (в замере 11.09 это был `404` за `0,19 с`; холодный подъём — `1,1 с`). `404` на несуществующую модель = **доказательство доставки**, а не поломка. `200` будет уже платным.
- `GET /__frontdoor/api/status` → в JSON поле **`routed.<prefix>` = 1** (`frontdoor-proxy.js:510` `routed: {...routedCounts}`), при этом **`active` не сменился** — это и есть «маршрут по модели, а не по активному провайдеру». Есть и таймстемпы — `routed_last.<prefix>` (`:511`).
- **`502`** — шлюз выбран префиксом, но поднять не удалось. Текст фронт-дора дословно несёт разгадку (`:720`): `… (шлюз выбран префиксом модели \`<prefix>/\`, активный бэкенд ни при чём)`. Наблюдалось в бою: `seekai/claude-opus-5` → `502 «шлюз выбран префиксом модели seekai/»` (`hub-tasks.md:254`).
- **`400`** — со своей подсказкой: в реестре нет `<prefix>-routes-modelmap.json`, либо `default` не задан (`:582`, `:592`; подсказка прямо говорит «открой :8200 → вкладка Маршруты», либо `/model <prefix>/<модель>` явно).
- `503` — front-door жив, но дашборд не выбрал провайдера (`stateCache.error`, `:605`).

**Настоящая команда `/model` — внутри сессии Claude Code:** `/model uk` (или `uk/claude-opus-4-8`). Канон-приёмка: «`/model uk` … отвечает 200 через front-door» (§6 хендоффа, строка 210). Это **платный** путь — в разведке не запускаю.
🪤 **Префикс должен быть в `CC_MODEL_PREFIX`** (`transparent-proxy.js`) — иначе префиксного пути у шлюза **нет вовсе** и `/model uk` вернёт 400 «карта не адресуется» (§ Шаг 3.2 хендоффа, строки 142-144). Для getunikey это `uk` (кандидат).

**Как проверено:** чтение `routing/frontdoor-proxy.js` (строки 37, 117, 473-511, 557-599, 605, 711-729, 936), шапки и константы песочниц трёх `tools/check-frontdoor*` и `check-routes-default.js`, канон [[Роутинг по модели, а не по активному провайдеру]] § «Приёмка в бою». **Ничего из сетевого не запускалось.**

### Пункт 6 — почему баланс может показывать «—» (суть + какие проверки это ловят)

Поломка была **двухслойная**; обе части — в общем коде, который унаследует и getunikey.

- **Слой 1 — сервер, гейт по `status`.** `newapiApplyBalance()` (`routing/transparent-proxy.js:9043`) пишет цифры в запись **только под условием `if (bal.status === 'live')`** (строка **9084**; в вики указана «~8906» — номера сдвинулись). Внутри: `target.balance = bal.balance; target.balanceSource = bal.balanceSource;` (`:9089-9090`). Вне блока безусловно обновляются `target.status = bal.status` (`:9048`) и `target.balanceCheckedAt` (`:9049`). ⇒ Источник без `status: 'live'` → чек **проходит**, штамп свежий, а `balance`/`balanceSource` **не записаны** → ячейка пустая. Именно на это обжёгся AIKeysAPI (его cookie-путь возвращал объект без `status`; поймано сравнением — свежий штамп при отсутствии цифр). **Фикс: добавить `status: 'live'` и `balanceSource: 'self'` в возвращаемый объект.**
- **Слой 2 — клиент, гейт по префиксу ключа.** `newapiBalanceCell(s, kJ, prov, sym = '$', keyOk = isRealKey)` (`routing/proxy-dashboard.html:14020`) первой строкой отсекает запись через `keyOk(s.api_key)`, дефолт — `isRealKey(k) { return /^sk-/.test(String(k || '')); }` (**:10444**). Ключ без `sk-` → `NO_KEY_BALANCE` («—») **до** чтения цифр, даже когда баланс уже лежит в пуле. Обёртки передают свой пятый параметр: `akBalanceCell` → `newapiBalanceCell(s, keyJ, 'ak', '$', akIsRealKey)` (**:18167**), `rmBalanceCell` → `rmIsRealKey` (**:18813**). Остальные (`ar/go/kk/ap/hn/jw/sk` — строки 14146, 15527, 16066, 16602, 17313, 19165, 19706) — по дефолту.
- 🪤 **Для getunikey слой 2 скорее всего пройдёт сам:** ключ начинается с `sk-` (§5.5 хендоффа) → дефолтная `isRealKey` вернёт true. Но канон: «смотреть на факт, а не на префикс». Ключи без `sk-` → понадобится свой `ukIsRealKey`, как у `ak`/`rm`.

### Пункт 7 — что требует рестарта `:8200`, а что подхватывается на F5

**Корень различия — откуда берётся каждый байт страницы.**

- **HTML-разметка вкладки — с диска на КАЖДЫЙ запрос, рестарт не нужен.** `transparent-proxy.js:24809-24818`: на `GET /` (и `/__switch/`) делается `fs.readFileSync(path.join(__dirname, 'proxy-dashboard.html'), 'utf8')` (`:24811`) и отдаётся с `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` (`:24814`). Комментарий тут же (`:24829-24831`) дословно: *«HTML читается с диска на каждый запрос и с no-store (см. выше) — страница становится новой сразу, без перезапуска. А роуты живут в памяти процесса, и он остаётся старым»*.
- **Фронтовый JS вкладки — тоже на F5.** Все 10 `<script>`-блоков лежат **внутри** `proxy-dashboard.html` и едут тем же `readFileSync`. Отдельные вендорные файлы (`routing/vendor/*.js|css`, напр. `proxies-tab.js`) отдаются так же — `:24780-24803`, `fs.readFileSync(file)` на `:24793`, у `models-tab*` принудительно `no-cache` (`:24796`).
- **Серверный код и роуты — только рестарт.** Всё в `routing/transparent-proxy.js` (хендлеры `handleKk*`/`handleAk*`, `CC_MODEL_PREFIX`, `DEFAULT_TABS_VISIBLE`, `keepaliveInstances()`, новые `if (req.url === '/__switch/api/xx/…')`) живёт в памяти процесса, поднятого на старте. Новый роут до рестарта даёт **404** при целом коде. Симптом — `check-after-restart.js:8-13`: *«HTML читается с диска на КАЖДЫЙ запрос (то есть новый), а роуты и функции лежат в памяти процесса (то есть старые). Отсюда классика этого проекта — «правка в файле есть» принимают за «работает в бою», и красная проверка приходит через сутки»*.

⇒ **Правило для getunikey** (совпадает с §6 хендрофа, строки 207-209):
