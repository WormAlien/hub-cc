## Правка 1 — распознавание имени шлюза (`statusline-autoreger.sh`, блок с :149)

`case "$model_id" in */*)` заменён на две ветки. Голое имя ищется в реестре **после среза
суффикса окна** (`${model_id%%\[*}`) — ровно как `routeByModel` (`frontdoor-proxy.js:386`,
`bare = j.model.trim().replace(/\s*\[[^\]]*\]\s*$/, '')`). Промах по реестру штатен: обычное
имя модели (`claude-opus-5`) тоже проходит через эту ветку и ничего не меняет — так же
устроен и front-door, он `reg.get()` делает для каждого имени без слэша.

Заведены три флага для нижних блоков:

| флаг | значение |
|---|---|
| `route_prefixed` | шлюз назван в имени модели (любая из двух форм) → читать **routes**-карту |
| `route_bare` | модель НЕ названа → тир `default`, второго слова в рендере нет |
| `win_suffix` | `[1m]` исходного имени; снимается ДО среза префикса, иначе у голого имени источника суффикса не остаётся |

## Правка 2 — выбор карты и тир `default` (блок `map_target`)

- `route_prefixed=1` → `$ROUTING/${map_prefix}-routes-modelmap.json`, иначе прежний
  `${map_prefix}-modelmap.json`. Это зеркало `readModelMap(routes)`
  (`keepalive-proxy.js:127-139`), куда флаг приезжает заголовком `x-route-prefixed`.
- `route_bare=1` → `mm_tier="default"` **до** проверок gpt/opus/sonnet/haiku: имени модели
  нет вовсе, тир по нему не выводится.
- Условие показа стрелки: у голого имени сравнивать не с чем (`mm_val != mm_bare`
  бессмысленно), поэтому для него стрелка рисуется всегда, когда цель в карте есть.
- `[1m]` дописывается из `win_suffix`, а не из `case "$model_id"` — после среза префикса
  у голого имени `model_id` пуст.

## Правка 3 — рендер без удвоения имени

```
route_bare=1, цель есть:  agentrouter→opus-5[1m]        ← слева шлюз, справа развёртка
route_bare=1, цели нет:   agentrouter→?  (красный `?`)  ← front-door отдаст 400
слэш-форма и обычная:     прежний рендер, байт в байт
```

бар значило бы показать здоровую строку на запросе, который наверх не уйдёт.

## Замер на живом стеке: `/model agentrouter` сейчас отдаёт 400

Проба front-door `:20100` (POST `/v1/messages`, `max_tokens:1`; денег не стоит — ответ
приходит от самого front-door, наверх не уходит ничего):

```
$ curl -X POST http://127.0.0.1:20100/v1/messages -d '{"model":"agentrouter",...}'
400
{"type":"error","error":{"type":"api_error","message":"front-door: шлюз «agentrouter»
выбран префиксом, но модель по умолчанию у него не задана. …"}}
```

Причина — **не** статуслайн и не карта: `ar-routes-modelmap.json` на диске заполнен
(`default: claude-opus-5`). Виноват живой реестр `~/.claude/backends.json`:

```json
"agentrouter": { "upstream": "http://localhost:20133", "keyFile": null, "modelmap": null, … }
```

`routesMapFor()` (`frontdoor-proxy.js:376`) выводит имя routes-карты **из
`state.modelmap`** и при `null` возвращает `null` → `noTarget` → 400. Регресс это уже
знает и краснеет ровно на этом:

```
$ node tools/check-routes-default.js
  ok   ... 20 проверок ...
  FAIL в живом реестре у локальных шлюзов с префиксом карта проставлена: без карты: agentrouter
[FAIL] 1 из 21
```

Это **чужой предсуществующий красный**, не регресс моей правки: ассерт «локальная ветка
берёт карту из CC_MODEL_PREFIX, а не хардкодит null» по исходнику **зелёный**, то есть
`registrySeedEntry` в `transparent-proxy.js` уже починен. Реестр писал живой `:8200`,
который держит **старый** `transparent-proxy.js` (вика: «Приёмка только после рестарта
`:8200`»). Рестарт мне запрещён, поэтому состояние остаётся как есть.

### Что это меняет для бара

Бар обязан не врать **в этом** состоянии тоже. `map_prefix`-таблица дала бы
`agentrouter→opus-5[1m]` на запросе, который фактически вернёт 400. Поэтому для **голого
имени** путь к routes-карте берётся оттуда же, откуда его берёт front-door — из поля
`modelmap` записи реестра, а не из своей таблицы префиксов.

🪤 Различие узкое и намеренное: у слэш-формы (`agentrouter/claude-haiku-4-5`) front-door
`routesMapFor` **не зовёт** вовсе — он срезает префикс и ставит `x-route-tier`, а карту
разрешает уже keepalive из своего `MODELMAP_FILE`. Значит поле реестра там ни при чём, и
таблица префиксов для неё остаётся верным источником.

## `check-statusline` флапает — и это НЕ моя правка (доказано)

Один прогон из ~8 краснеет «сегментов потеряно: 3-4». Причина: тест сравнивает **два
отдельных запуска бара** байт в байт (`out.replace(seg, '') === plain`), а бар читает живые
файлы пула. Между запусками дашборд успевает подменить активный ключ, и меняется баланс —
замер шести прогонов подряд:

```
$16.33 🎁28   $16.33 🎁28   $16.33 🎁28   $16.33 🎁28   $16.33 🎁28   $8.53 🎁28
                                                                     ^^^^^ ключ подменён
```

Изоляция теста (`HOME` → пустой профиль) провайдера гасит, но `🎁`-счётчик и файлы пула
читаются от **`ROOT`** репо, а не от `HOME`, поэтому в изоляцию не попадают.

Проверка причинности — прогон того же теста против **версии бара из `HEAD`** (мои правки не
участвуют вовсе, `git show HEAD:routing/statusline-autoreger.sh`):

```
$ for i in 1..8; do node _sandbox/check-HEAD.js | tail -1; done
[X] сегментов потеряно: 3      ← флап есть и на СТАРОМ баре
[OK] ... × 7
```

Значит флап предсуществующий, чиню не он. Мой бар в тех же условиях: **8 прогонов подряд
зелёные** (25/25 проверок).

## Найдено и починено по дороге: регистр имени и ложное «это шлюз»

Стресс-прогон бара по нестандартным `model.id` (9 форм) вскрыл два бага — оба нашлись
только замером, ни один не был виден в коде.

### 1. Регистр имени шлюза бар игнорировать не умел

Front-door ищет `reg.get(bare.toLowerCase())` (`frontdoor-proxy.js:401`), и регресс
`check-routes-default` уже требует от него «регистр имени не важен». Бар же сравнивал
строки как есть: `/model AIPM/claude-opus-4-6` уезжал на aipm, а бар показывал активный
шлюз — вранье про маршрут, ровно того класса, что и заявка.

Лечится `shopt -s nocasematch` **на один блок** (`${x,,}` нельзя — bash 4+). Каноничное
написание берётся **из файла** первой группой regex, а не как набрал человек: подписи
ниже (`case "$raw_target"`) сравнивают точные строки, и `AIPM` провалился бы в catch-all
без тир-карты и без баланса. `shopt -u nocasematch` сразу после блока — иначе
регистро-зависимые `Custom*` и `*[Oo]pus*` ниже начали бы совпадать не с тем.

### 2. 🪤 Признаком попадания нельзя брать «`raw_target` не пуст»

Первая версия правки объявляла шлюзом **любое** имя модели: `claude-opus-5[1m]` печатался
как `agentrouter→?`. Причина — блок front-door **выше** (`:143`) уже заполняет
`raw_target` активным бэкендом из `active-backend.json`, поэтому проверка «не пуст» верна
всегда. Признак попадания только один — имя нашлось в реестре; заведена отдельная
переменная `mp_hit`.

Замер до/после на именах, которых в реестре заведомо нет:

```
было:  claude-opus-5[1m]      → agentrouter→?                    ❌ выдумал шлюз
       deepseek-v4-flash[1m]  → agentrouter→?                    ❌
стало: claude-opus-5[1m]      → agentrouter/claude-opus-5[1m]    ✅ как было до правки
       deepseek-v4-flash[1m]  → agentrouter/deepseek-v4-flash[1m] ✅
       AGENTROUTER[1m]        → agentrouter→…                     ✅ регистр не важен
       AgentRouter/claude-sonnet-5 → agentrouter/claude-sonnet-5→rt-sonnet ✅
```

Оба закрыты ассертами (регресс дорос до **46 проверок**, прогоны подряд зелёные):
три имени «не выдаётся за шлюз», верхний регистр резолвится, в баре каноничное имя, а не
набранное, смешанный регистр в слэш-форме.
