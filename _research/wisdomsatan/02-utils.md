## Ключевая механика (что клон наследует)

- **`kkLoad`** — id-миграция: старые аккаунты жили по `api_key`, теперь у каждого стабильный
  `id` вида `kk_<ts>_<i>_<rnd>`. Дубли id не трогаются, первый побеждает. Плюс разовый перенос
  ручных `grantManual`/`bonus`/`referral` в анкер через `newapiMigrateAnchors`.
- **`kkKeepaliveSpawn`** — поднимает второй экземпляр `keepalive-proxy.js` на своём порту,
  параметризуя его env'ом (`PORT`/`UPSTREAM`/`KEY_FILE`/`MODELMAP_FILE`). Сначала проверяет
  порт на занятость через `net.createServer` → если занят, возвращает `{ ok: true, already: true }`.
- **`kkProbe`** — `GET /v1/models` с CC-заголовками: 200 = live, 401/403 = dead, иначе unknown.
- **`kkBalance`** — обёртка над общим `newapiBalance` (определение `:7980`).

## Вызовы shared-функций с хостом/тегом строкой

### Правят поведение — менять обязательно

**`newapiBalance({...})`** (вызов 12981–12989, определение `:7980`). Литерал `host` уходит в ТРИ места:
`lib.hostGate(host, fn)` (:7987, шлюз частоты запросов к хосту), `newapiResolveProfile(host, target)`
(:8030, резолв профиля и кук для точного баланса), `lib.quotaPerUnit(host)` (:8070), плюс в логи
(:8081, :8095). **Оставить `kktoken.cc` = новый шлюз ходит в чужой rate-gate и резолвит чужой
профиль → точный баланс молча деградирует в прикидку.**

**`newapiApplyBalance(target, bal, { provider: 'kktoken' })`** (12992, определение `:8517`) — тег полным именем.
