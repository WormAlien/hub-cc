## 2. `killPortListeners` (18716) — НЕ горячий, проверено

`keepaliveBring()` зовётся часто (десятки мест: автоподъём шлюзов по префиксу), но
`killPortListeners` внутри достижим только двумя ветками:
- `opts.force` — кнопка «🔄 перезапустить» в Health, явное действие;
- порт занят, но `/status` молчит — снятие зомби, аварийный случай.

Обычный путь выходит раньше: `portAnswers(port, statusPath)` → `return { already: true }`.
Оставляю как есть.

## 3. Горячий путь: подтверждение, что health опрашивается сам

`routing/proxy-dashboard.html`:
- стр. 27086 — `loadHealth()` на загрузке страницы, **безусловно** (бейдж N✓/N↓);
- стр. 27097 — `setInterval(..., 15000)` пока вкладка Health открыта.

То есть ручка бьёт по event loop каждые 15 с при открытой вкладке и один раз на каждом
открытии дашборда. Это и есть «дашборд встаёт на секунды».

## 4. Падающий тест написан и КРАСНЫЙ

`tools/check-health-async.js` — 4 проверки. Прогон ДО правки кода:

```
1. Горячий путь: GET /__switch/api/health
  ✗ handleHealth не зовёт синхронные внешние команды
      строка 4279: const out = execFileSync('netstat', ['-ano'], { encoding: 'utf8' });
      строка 4441: const g = (...a) => execFileSync('git', a, { cwd: repo, encoding: 'utf8' }).trim();
  ✗ handleHealth получает данные о портах асинхронно (await)
  ✗ handleHealth получает состояние git асинхронно (await)

2. Механика: async не держит event loop, sync держит
      блокировка event loop на 5× netstat: sync 260 мс · async 25 мс
  ✓ асинхронный netstat не блокирует event loop

✗ провалено 3, пройдено 1     EXIT=1
```

Грабля в самом замере (поймана и записана в тест): снимать `clearInterval` сразу после
блокирующей работы нельзя — самый большой разрыв живёт в тике, который loop выполнит
ПЕРВЫМ ШАГОМ после разблокировки. Первая версия показывала 21 мс блокировки там, где
стенные часы честно мерили 250 мс. Лечится задержкой 30 мс перед снятием таймера.

Второй замер: `netstat -ano` на этой машине сейчас **48–61 мс** (владелец мерил
159–185 мс — цена растёт с размером таблицы соединений). Поэтому в тесте прогон 5×,
иначе один вызов тонет в шуме планировщика.

## 5. Правка

`routing/transparent-proxy.js`:
1. Стр. 17 — добавлен `execFileAsync` (`util.promisify(child_process.execFile)`) с
   развёрнутым комментарием, ПОЧЕМУ он обязателен и почему точечные sync в путях по
   кнопке оставлены.
2. `handleHealth`, блок слушателей — `execFileSync` → `await execFileAsync`, плюс
   `maxBuffer: 16 МБ` (дефолтный 1 МБ мал для `netstat -ano` на машине с флотом:
   ENOBUFS обрубил бы вывод, и таблица портов молча приехала бы неполной).
3. `handleHealth`, блок git — `execFileSync` → `await execFileAsync` + `timeout: 8000`.
   Здесь цена блокировки ВЫШЕ, чем у netstat: `git fetch` ходит в сеть. Добавленный
   timeout закрывает и отдельную дыру — зависший fetch (VPN лёг, github не отвечает)
   растягивал health до бесконечности.

## 6. Замер ДО/ПОСЛЕ

Живой `:8200` (pid 8912) ДО правки, замер по HTTP:
```
HTML в покое:         ttfb  25 мс
health:               ttfb 2214 мс
HTML во время health: ttfb  140 мс   <<< блокировка
```

ПОСЛЕ на живом `:8200` измерить НЕЛЬЗЯ: процесс крутит старый код, пока владелец не
перезапустит, а рестарт рвёт его сессии Claude Code. Поэтому форма кода измерена
изолированно — `.tmp-split/bench-health.js`: два песочных сервера на тех же внешних
командах, клиент ОТДЕЛЬНЫМ процессом, три прогона:

```
ДО (sync)       HTML в покое 7 мс · HTML при health 1280 мс · health 1279 мс
ПОСЛЕ (async)   HTML в покое 2 мс · HTML при health   22 мс · health 1167 мс
--------------------------------------------------------------- в 58 раз меньше
повтор: 1261 → 26 мс (48×)  ·  1261 → 19 мс (66×)
```

Сама health не ускорилась (1,2–2,2 с — это сумма проб всех сервисов) и не должна: смысл
правки в том, что она больше НЕ ДЕРЖИТ процесс, пока считается.

🪤 Грабля замера, пойманная на себе: клиент обязан быть отдельным процессом. Пока сервер
заблокирован, клиент в том же процессе не получает даже событие `connect`, запросы уходят
в сокет уже после разблокировки — и sync-версия с 1,4 с блокировки показала «1 мс».
Первый прогон выдал «1 мс → 2 мс» и был выброшен.
