## 3. IMAP для купленных Google-почт

**Факт (отрицательный, с опорой).** **Реализации чтения почты по IMAP с паролем приложения
для Google в репо НЕТ.** Единственный IMAP-клиент — `freemodel/lib/timeweb-imap-client.js`, и он
подключается не к Gmail, а к **своему домену у хостера** (`TW_IMAP_HOST/USER/PASS`), то есть читает
свой catch-all ящик-ридер, куда сваливаются письма на любой `*@<домен>`. Логин — обычный
`LOGIN user pass` (`:196`), без OAuth.

Что находится по `gmail` в репо:
- `freemodel/lib/emailnator.js` — выдаёт **алиасы на gmail.com с точками** (`.Gmail` чип), это НЕ
  купленный ящик, читаются через сайт emailnator браузером, IMAP не при чём. Мотив — в
  `emailnator.js:37-38`: «ни один одноразовый домен у китайских панелей не проходит whitelist, а
  `@gmail.com` — проходит».
- `anymodel/anymodel_autoreger.js:74` — синтетический `${name}@gmail.com` как логин, не ящик.
- `routing/lib/outlook-pool.js:62-64` — в чеках магазина встречаются строки `gmail:пароль:2FA`
  (это GitHub-аккаунт, помечаются как НЕ ящики по base32-секрету).
- `routing/lib/outlook-pool.js:8-11` — прямой тезис: у Microsoft IMAP по паролю выключен
  (`AUTH=XOAUTH2 LOGINDISABLED`). Про Google аналогичной записи нет, но и кода тоже нет.

**Grep-подтверждение:** `grep -rni "imap|app password|1secmail|tempmail|temp mail|google app"`
по репо (без node_modules) — 16 файлов, из них IMAP-специфичных ровно два: `timeweb-imap-client.js`
и `outlook/*` (оба описаны выше). Упоминаний `1secmail`, `smtp.gmail`, `less secure`,
`imap.gmail.com` — **ноль**.

**Вывод:** если `getunikey` требует именно ящик с приёмом письма, механизма «купленный Google +
пароль приложения + IMAP» в репо нет — его пришлось бы писать с нуля (или тянуть `imapflow`).
Готовый и живой в репо есть только путь «свой домен + catch-all + IMAP».

## 4. Что нужно именно для 6-значного кода

**Факт.** В репо две рабочие реализации разбора 6-значного кода, обе с одинаковой главной
граблей: **цифры из адреса получателя матчатся раньше кода**.

Механизм (по `outlook/read-code.js:84-107`, образец — `timeweb-imap-client.js:160-177`):
1. **Строки-заголовки выбрасываются целиком** — `HEADER_LINE_RE` (return-path, delivered-to,
   received, from, to, …) плюс локализованные (`кому|от|дата|тема`).
2. **Строка, содержащая адрес ящика, выбрасывается** — иначе цифры из local-part адреса дадут
   ложный код.
3. Приоритет — «код рядом со словом»: `CODE_NEAR_RE = /(code|código|codice|kod|код|passcode|otp|pin)[^\d]{0,24}(?<!\d)(\d{6})(?!\d)/i`
   (в письме бывают номера договоров/телефонов в футере).
4. Резерв — точная 6-значная регулярка с негативным lookbehind/lookahead: `/(?<!\d)(\d{6})(?!\d)/`
   — **обязательно** `(?<!\d)`/`(?!\d)`, иначе 7-значное число разрежется в ложный код.

**Защита на стороне адреса** (`timeweb-imap-client.js:81-93`): локальная часть генерируется
ТОЛЬКО из букв (`randLocal()` без цифр) — комментарий `:82-84`: цифры в local-part матчатся
раньше OTP → «invalid code». Это дешевле, чем вычищать их постфактум.

**Сколько ждать.**
- `aikeysapi/auto-add.js`: `OTP_TIMEOUT_MS = 180000` (3 мин), поллинг каждые 3 с (`OTP_POLL_MS`),
  замер живого письма — ~17 с (комментарий, не константа).
- `timeweb-imap-client.js`: `waitOtp({ timeout: 120, poll: 5 })` — дефолт **120 с, поллинг 5 с**;
  в фильтре времени `sinceTs = Date.now() - 15000` (запас 15 с на рассинхрон часов, `:206`).
- `outlook/read-code.js`: общий потолок `TIMEOUT_MS = 60 * 1000`, осматривает до `MAX_ROWS = 3`
  верхних писем (вверху бывает реклама в тот же момент).

**Что при непрочтении.** Репо нигде не «угадывает» код и не продолжает без него — отдаёт явную
ошибку с кодом возврата:
- `aikeysapi`: `waitOtp` → `null` → `{ok:false, code:8, why:'код не пришёл за 180 с'}` (`:532`);
  если письмо пришло, но корда нет — строка в лог «письмо от панели пришло, кода не нашёл» + превью
  тела (`:474`); отдельный `code:8` = «почта», в списке кодов возврата `:71`.
- `outlook/read-code.js`: `{ok:false, error:'no_code'}` (код 1) / `'timeout'` (2) /
  `'session_expired'` (3) — разделение важно: «сессия погасла» = «человек, открой ящик и войди», а
  не «кода нет» (`:19-21`).
- `timeweb-imap-client.js`: `{ok:false, code:null, link:null}`; письмо с найденным кодом
  помечается `\Deleted` + `EXPUNGE` (`:268-272`) — «не перечитаем, ящик не пухнет».

**Применимо к `getunikey` (код 6 ЦИФР, не алфанумерики).** Ключевое отличие от `aikeysapi`, где код
алфанумерический: там резервная регулярка `\b[A-Za-z0-9]{6}\b` ловит `Random` из приветствия
ящика, и `aikeysapi` вынужден фильтровать письма по бренду отправителя (`isPanelMail`). Для чисто
цифрового кода берём образец из `timeweb-imap-client.js` / `outlook/read-code.js` — он строже и уже
отработан на цифрах: `(?<!\d)(\d{6})(?!\d)` + отсев строк с адресом и заголовков.

**Проверено.** Прочитаны `outlook/read-code.js:79-122`, `timeweb-imap-client.js:80-177`,
`aikeysapi/auto-add.js:309-355, 462-480`.

## 5. Сравнение путей

**Факт.** Три пути, каждый с опорой на код репо:

| | (а) временные ящики API | (б) купленный Google + app password + IMAP | (в) свой домен catch-all + IMAP |
|---|---|---|---|
| Код в репо | ГОТОВ, обкатан | **НЕТ ни строки** | ГОТОВ (`timeweb-imap-client.js`) |
| Где вход | `MAIL_PROVIDERS` `aikeysapi/auto-add.js:440-459` | — | `freemodel/lib/timeweb-imap-client.js` |
| Цена запуска | 0 ₽ | ~10 ₽/ящик | цена домена + хостинг почты |
| Проходит вайтлист | НЕТ (rumeng: отбит по суффиксу до регистрации) | да (это и есть `@gmail.com`) | только если домен не одноразовый |
| Риск автоматизации | сервис лёг (guerrillamail) | Google режет автовход (по аналогии с MS) | нет |
| Чтение | HTTP API сервиса | IMAP (писать с нуля) | свой raw-TLS+IMAP клиент |

**Что дешевле ПО КОДУ, с опорой на факты:**
- (а) дешевле всех по старту: `makeInbox()` + двухступенчатая регулярка + фильтр письма уже есть
  (`aikeysapi/auto-add.js:440-480`). Но это ровно тот путь, что `rumeng` забраковал: «отвергаются по
  суффиксу ДО регистрации» (`rumeng/auto-add.js:57-58`).
- (б) дороже всего: в репо нет ни IMAP-зависимости (`imapflow`/`node-imap` не найдены), ни строчки
  кода под Gmail. Живая грабля родственного случая прямо в репо: у Microsoft IMAP по паролю
  выключен (`AUTH=XOAUTH2 LOGINDISABLED`, `outlook-pool.js:8-11`), и там ушли на чтение ЧЕРЕЗ БРАУЗЕР
  (`outlook/read-code.js`). Для Google подтверждения в репо нет, но и повода считать иначе — тоже:
  Google исторически режет «less secure apps» и требует OAuth/пароль приложения.
- (в) практический компромисс: если у `getunikey` вайтлист — свой домен его проходит (не суффикс из
  чёрного списка), а клиент уже написан и обкатан. Но это НЕ «купленный Google», домен надо иметь.

**Готовая в репо альтернатива вайтлисту** — emailnator (`@gmail.com` с точками) + Playwright,
механика в `rumeng/auto-add.js` и `freemodel/lib/emailnator.js`. Минус, зафиксированный живьём:
ящики переиспользуются, в них чужие письма, обязателен `fromHint` и фильтр по свежести
(`rumeng/auto-add.js:63-65`).

**Итог:** «купленный Google по 10 ₽ + пароль приложения + IMAP» в репо не реализован и является
самым дорогим путём по коду; самый дешёвый — (а), но он же и самый хрупкий к вайтлисту. При
неизвестном вайтлисте `getunikey` начинать логично с (а) как проверки гипотезы, а при отказе по
суффиксу — идти на emailnator или свой домен, но не на IMAP-Google.

**Проверено.** Свод §1-§4 и §2а; все цитаты с указанием `файл:строка`. Ни одного сетевого запроса к
`getunikey` не делалось; пароли/куки/реальные адреса в отчёт не попадали.
