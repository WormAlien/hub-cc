### Границу «где keepalive инжектит `[1m]`» определяет код, а не глаз

`keepalive-proxy.js` спавнится из `transparent-proxy.js` ровно **11 раз**
(`KEEPALIVE_PROXY_FILE`, строки 8082 / 13304 / 13993 / 14140 / 15329 / 16000 / 16911 /
17801 / 18452 / 19170 / 20136) — по функциям `arKeepaliveSpawn`, `goKeepaliveSpawn`,
`kkKeepaliveSpawn`, `apKeepaliveSpawn`, `hnKeepaliveSpawn`, `akKeepaliveSpawn`,
`jwKeepaliveSpawn`, `skKeepaliveSpawn`, `tsKeepaliveSpawn`, `tbKeepaliveSpawn`,
`xpKeepaliveSpawn`. Ни один спавн не выставляет `MODEL_ECHO_INJECT=0`, значит
`INJECT_1M` у всех одиннадцати включён.

У клиента этот же список **уже объявлен** — `KEEPALIVE_POLL_TABS`
(`proxy-dashboard.html:13189`), 11 записей `имя шлюза → [префикс, url]`, ровно те же
шлюзы. Второй копии списка не заводим, берём эту. `cun`, `conduit`, `ourtoken`,
`custom`, `freemodel`, `vyceai`, `svrtr`, `helpcoder` keepalive не имеют — им остаётся
только regex-правило, как у сервера.

### Почему нельзя просто «дописать `[1m]` всем»

`withCtxSuffix()` — общая для ~20 вкладок (`copyModelCmd` зовут 20 мест). Безусловный
суффикс сломал бы:
- **AIKeysAPI** — решение владельца 12.09: `[1m]` не вешаем и снимаем (`NO_1M_GATEWAYS`);
- **паритет с сервером** — регресс `check-1m.js:211` сверяет `withCtxSuffix(id)` с
  `normalizeCcModel(id)` буквально на 10 именах, включая `hcnsec/kimi-k3` и `ComboWombo`,
  которым сервер суффикс НЕ вешает.

Поэтому «это шлюз» и «у шлюза есть keepalive» — два разных факта, и оба приходят
**от вызывающего**, который их знает (реестр вкладки «Маршруты» / сама вкладка шлюза),
а не из третьей таблицы во фронте.

## План правки

1. `withCtxSuffix(id, gw)` — второй, необязательный аргумент «шлюз, которому
   принадлежит имя». Без него поведение прежнее (regex-паритет с сервером сохраняется).
2. `routesCmdHtml()` — `withCtxSuffix(p.name, p.name)`; бейдж `<code>` и буфер строятся
   из ОДНОЙ переменной.
3. 11 вкладок шлюзов с keepalive — `copyModelCmd(id, '<шлюз>')`.
4. `cunNormalizeCcModel()` (:10614) — делегирует в `withCtxSuffix`, дубль снят.
5. `tools/check-1m.js` — новые инварианты в сверку.

## Шаг 1 — `withCtxSuffix(id, gw)` ✅

`routing/proxy-dashboard.html:10264`. Второй аргумент — **вкладка**, с которой нажали
кнопку. Без него поведение прежнее (один regex), поэтому паритет с сервером на
префиксных именах не ломается.

Ветки поверх regex — обе скопированы с сервера:
- голое имя шлюза (`tab === bare`) → `[1m]`, как `slash < 0 && CC_MODEL_PREFIX[gw]`;
- вкладка есть в `KEEPALIVE_POLL_TABS` → `[1m]`, как безусловный `echoModelFor()`;
- `NO_1M_GATEWAYS` (копия серверной, сверяется регрессом) → суффикс снимается.

🪤 **Вторая ветка сознательно НЕ смотрит на префикс `<шлюз>/<модель>` внутри имени.**
Догадка по префиксу дала бы `hcnsec/kimi-k3[1m]` там, где сервер оставляет голое имя, и
`check-1m.js:211` (буквальная сверка `withCtxSuffix` ↔ `normalizeCcModel`) упал бы —
то есть копии разошлись бы заново, ровно тем способом, от которого чокпоинт и заведён.

## Шаг 2 — `routesCmdHtml()` ✅

`routing/proxy-dashboard.html:9581`. Было `'/model ' + p.name`, стало
`'/model ' + withCtxSuffix(p.name, p.name)`.

Имя шлюза передаётся вторым аргументом, потому что здесь этот факт **известен точно** —
`p.name` это ключ реестра `backends.json`, а не строка от пользователя. Гадать «нет
дефиса, значит шлюз» (как приходится серверу) не нужно.

Бейдж `<code class="rt-badge">` и буфер строятся из **одной** переменной `cmd`: владелец
видит ровно то, что вставит. Расхождение в один суффикс — это и есть тихий 200k.

## Шаг 4 — третья копия правила снята ✅

`cunNormalizeCcModel()` (:10823) теперь `return withCtxSuffix(m)`. Своя строка была не
идентична общей ветками вокруг regex: на `aikeysapi/gpt-5.6-sol` она вешала `[1m]`,
который сервер снимает. Второй аргумент не передаём — у cun.ai keepalive нет (ни в
`KEEPALIVE_POLL_TABS`, ни спавна `keepalive-proxy.js`), значит безусловной инъекции в
ответ ему никто не делает.

🔴 **Найдено по дороге, в регрессе:** `check-1m.js:190` ищет функцию шаблоном
`/function withCtxSuffix\(id\) \{/`. Новая сигнатура `(id, gw)` под него не подходит, и
`ctxSuffix` стал бы `null` — а дальше стоит `if (ctxSuffix && srvNorm)`, то есть
**сверка клиента с сервером молча выключилась бы**, тест остался бы зелёным. Тот же
класс, что и сама заявка: не ошибка, а тихая потеря защиты. Правится в шаге 5.

### 🔴 Побочная находка: вкладка AIKeysAPI нарушала решение владельца

Две строки в таблице помечены красным **не** как ожидаемый результат правки, а как баг,
которого в задании не было. Кнопки вкладки AIKeysAPI копировали
`/model gpt-5.6-sol[1m]`: её модели (`gpt-5.6-sol|luna|terra`) попадают в `CC_1M_RE`,
а про исключение `NO_1M_GATEWAYS` клиент не знал вовсе.

То есть решение 12.09 («AIKeysAPI — дорогие запросы, окно 1M не заявляем, нужен ранний
автокомпакт») держалось только на сервере: `settings.json` через `normalizeCcModel()`
суффикс снимал, а команда с кнопки его возвращала. Владелец, скопировавший модель с этой
вкладки, получал ровно то окно, от которого там уходили.

Теперь вкладка передаёт своё имя, срабатывает та же ветка `NO_1M_GATEWAYS`, и результат
совпадает с сервером. Регресс сторожит это в двух местах: построчной сверкой копии
списка с серверной и явной проверкой «у AIKeysAPI суффикса нет».
