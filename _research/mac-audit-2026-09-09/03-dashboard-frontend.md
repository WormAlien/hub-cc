### [BROKEN] Кнопка «🔄 Рестарт дешборда» зовёт `.bat` — на маке файла нет
- **Где:** `routing/proxy-dashboard.html:736` (кнопка), `:23246-23257` (`launchBat`), `:25402` (второй вызов из поп-апа «дашборд обновлён»)

Расширение `.bat` — Windows-only; на маке эквивалент лежит рядом (`HUB.command`, `DASHBOARD.command`, `install-mac.sh` в корне репо), но фронт про них не знает. 'restart-dashboard.command' : 'restart-dashboard.bat')` — но тогда `.command` надо создать (сейчас его нет).
- **Уверенность:** CONFIRMED (само наличие `.bat` в разметке; реакция сервера на несуществующий скрипт — зона агента №2)

### [COSMETIC] Спрайты эмодзи пекутся шрифтом `Segoe UI Emoji`, которого на маке нет

### [DEGRADED] Ретина-мыло: канвасы «куча» и «костёр» не масштабируются по devicePixelRatio
- **Где:** `routing/proxy-dashboard.html:2405` — `W = canvas.width = w; H = canvas.height = h;` внутри `setBounds()` функции `makeFigure`. Оба вызова: `:3441` (`#cPile`, 340×330) и `:3454` (`#cFire`, 360×330). Ресайз идёт тем же путём: `:3702` → `:2841 resize(w,h)` → `:2844 setBounds(w,h)`
- **Что видит пользователь на маке в Safari:** вкладка «Финансы», две главные фигуры — куча 💩 и костёр 🔥 вместе с логотипами Claude Code и GitHub и цепью — заметно мыльные, будто картинку растянули. Особенно бросается в глаза на тонких элементах: звенья цепи и контур марки GitHub. Рядом на той же вкладке переключатель «куча / граф» — и **граф выглядит резким**, потому что он единственный сделан правильно.
- **Почему:** backing store канваса задаётся в CSS-пикселях (`canvas.width = 340`), а CSS растягивает его на бокс `.fig` (`#finTab .fig canvas{position:absolute;inset:0}`, `:873`) размером те же 340 CSS-px. На Retina это 680 физических пикселей, отрисованных из 340 — двукратное растяжение. На Windows-мониторе владельца `devicePixelRatio` = 1 (или 1.25/1.5), и дефект почти не виден — поэтому его и не поймали. Слой графа (`:3052-3313`) DPR учитывает: `DPR = Math.min(2, window.devicePixelRatio || 1)` (`:3305`), `canvas.width = Math.round(W * DPR)` (`:3307`), `ctx.setTransform(DPR,0,0,DPR,0,0)` (`:3234`) — то есть в файле уже лежит готовый образец правильного кода.
- **Фикс:** повторить схему графа в `setBounds` (`:2404-2419`):
  ```js
  function setBounds(w, h) {
    const dpr = Math.min(2, window.devicePixelRatio || 1);
    W = w; H = h;
    canvas.width  = Math.round(w * dpr);
    canvas.height = Math.round(h * dpr);
    canvas.style.width  = w + 'px';
    canvas.style.height = h + 'px';
    // ...дальше стены считаются от W/H в CSS-пикселях, как и было
  }
  ```
  и в начале каждого кадра отрисовки — `ctx.setTransform(dpr,0,0,dpr,0,0)` перед `ctx.clearRect(0,0,W,H)` (`:2832`). Спрайты (`sprite()` `:2232`, `markSprite()` `:2290`, `discSprite()`) при этом надо печь в `px * dpr` — граф это уже делает: `discSprite(Math.round(d * DPR), …)` (`:3255`).
  ⚠ `canvas.style.width/height` выставить **обязательно**: сейчас размер держит CSS-правило `inset:0`, и после умножения `canvas.width` на 2 без явного CSS-размера фигура раздуется вдвое.
- **Уверенность:** CONFIRMED (в `setBounds` нет ни `devicePixelRatio`, ни `setTransform`; grep по `DPR` даёт только строки слоя графа)

### [COSMETIC] Скроллбары принудительно классические — на маке это выбивается из системы
- **Где:** `routing/proxy-dashboard.html:74-77` — `*::-webkit-scrollbar { width: 9px; height: 9px; }` и три правила для `thumb`/`track`, все на универсальном селекторе `*`
- **Что видит пользователь на маке в Safari:** во всех прокручиваемых блоках дашборда постоянно висит серая полоса 9 px, тогда как в остальных приложениях macOS полосы прокрутки — накладные (overlay) и прячутся сами. Плюс эти 9 px отъедаются из ширины контента, а не рисуются поверх.
- **Почему:** как только `::-webkit-scrollbar` стилизован, WebKit переключается с накладных полос на классические, занимающие место в потоке. На Windows полосы и так всегда занимают место, поэтому вёрстка под это и делалась.
- **Фикс:** это вопрос вкуса, а не поломки. Если нужна «маковость» — обернуть в `@supports not (-webkit-touch-callout: none)` или в медиа-запрос по указателю, но проще оставить: единообразие дашборда между машинами скорее плюс. Отмечено, чтобы не искали причину, если владелец скажет «полосы какие-то виндовые».
  Отдельно: `scrollbar-width` / `scrollbar-color` (стандартный путь, который Safari игнорирует) в файле **не используются вообще** — то есть выбран ровно тот механизм, который Safari понимает. Здесь всё сделано верно.
- **Уверенность:** CONFIRMED

### [ОК, не находка] Голос, аудио и разрешения — уже сделаны кросс-браузерно
Проверено, потому что это самая «сафарная» часть дашборда. Здесь чинить нечего:

- `:29109` — `LGC_VOICE_MIMES = ['audio/webm;codecs=opus', 'audio/webm', 'audio/mp4']`, перебор через `MediaRecorder.isTypeSupported` (`:30401-30409`). `audio/mp4` — ровно путь Safari, где MediaRecorder отдаёт AAC. Комментарий на `:29106` это и объясняет.
- `:29139` — `const AC = window.AudioContext || window.webkitAudioContext;` — префикс учтён.
- `:29133` — автоплей-политика описана и обходится армированием по жесту (`:29148`, `addEventListener('keydown', lgAudioArm, {passive:true})`).
- `:30442-30450` — `navigator.permissions.query({name:'microphone'})` обёрнут в `try/catch` с возвратом `''`. В Safari `microphone` в Permissions API нет и запрос бросает — код это переживает и просто идёт спрашивать.

### [DEGRADED] «🔗 Поделиться» на Safari всегда будет требовать лишний клик

- **Почему:** WebKit разрешает `navigator.clipboard.writeText()` только в пределах жеста пользователя, и `await` на сетевом запросе этот жест съедает. Второй эшелон `copyToClipboard` — `document.execCommand('copy')` (`:24060`) — требует жеста ровно так же, поэтому тоже вернёт `false`.  
  ```js
  // внутри onclick, ДО любых await:
  const p = fetch('/__switch/api/ar/share', {...}).then(r => r.json()).then(d => d.share || '');
  try {
    await navigator.clipboard.write([new ClipboardItem({ 'text/plain': p.then(t => new Blob([t], {type:'text/plain'})) })]);
  } catch { /* дальше как сейчас — окно с кодом */ }
  ```
  `ClipboardItem` с промисом WebKit поддерживает именно для этого случая. Работа при этом не переделывается: окно `openShareCodeModal` остаётся страховкой.
  ⚠ Если трогать не хочется — это допустимо: механизм уже деградирует корректно и данные не теряются. Тогда стоит хотя бы смягчить текст плашки, чтобы на маке он не выглядел как поломка.
- **Уверенность:** PLAUSIBLE (поведение WebKit по гашению жеста на `await` — известное; конкретно на этой сборке Safari не замеряно. Проверка: нажать «🔗 Поделиться» на маке и посмотреть цвет плашки в окне кода.)
