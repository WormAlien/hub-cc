## 1. Шкала «Общий запас free-tier» (`renderGlobalGauge`)

**Файл:** `routing/proxy-dashboard.html`
`renderGlobalGauge()` — **22703**; `poolMoneyStat()` — **22682**; `MONEY_PROVIDERS` — **22504**;
`balanceUsable()` — **12860**; `balanceDenom()` — **12879**.

### Как суммирует

Цикл по `Object.values(MONEY_PROVIDERS)` → `moneySessions(mp.id)` (это `state[mp.stateKey]`,
массив аккаунтов из `/__switch/api/<p>/sessions`) → `poolMoneyStat(acc, mp.base)`:

```js
if (balanceUsable(s)) {
  if (s.balance < 0) { unknown++; continue; }
  sumBalance += s.balance;                 // ← сырое сложение поля `balance`
  sumGrant   += balanceDenom(s, base);
  withBalance++;
}
```

и наверху — `sumBalance += st.sumBalance; sumGrant += st.sumGrant;` по всем провайдерам.

**Никакой конверсии нет и не предполагается.** Складывается ровно поле `s.balance`.
Скрытые вкладки (`effectiveHiddenSet()`) выпадают из суммы целиком — их даже не запрашивают.

### Читает ли `sym`/`base` из MONEY_PROVIDERS

- **`base`** — читается: `p.stat(acc)` → `poolMoneyStat(acc, mp.base)`; база нужна только
  как знаменатель, чтобы не делить на ноль (fallback в `balanceDenom`).
- **`sym`** — читается **только в построчной подписи провайдера** под шкалой (**22732**):

```js
const money = st.withBalance
  ? `<span class="text-emerald">${p.sym || '$'}${st.sumBalance.toFixed(2)} доступно</span>`
  : …
```

- **В итоговой цифре шкалы `sym` НЕ читается — там `$` захардкожен (22752):**

```js
sumBalance > 0 ? `<span class="text-emerald">$${sumBalance.toFixed(2)} доступно из $${sumGrant.toFixed(0)}</span>` : '',
```

Символ валюты существует как **вывеска на строке одного провайдера**, а не как единица
измерения. Это прямо написано в комментарии над `MONEY_PROVIDERS`:

> `sym` — вывеска валюты: у XPeach 🍑, **курс к единице квоты тот же (quota/500000),
> поэтому цифры складываются с остальными без пересчёта**;

То есть автор карты явно зафиксировал допущение: **все `balance` — в одной единице
(доллар New API = quota/500000), а `sym` только рисуется.** 🍑 у XPeach — не другая
валюта, а шутка поверх тех же долларов. У `hcnsec` в карте (**22523**) стоит `sym: '$'` —
и это правильно, потому что складывается долларовое поле.

### Что будет, если один шлюз отдаст юани в поле `balance`

1. **Итоговая цифра шкалы соврёт вверх.** `$X доступно из $Y` сложит доллары с юанями как
   есть — ошибка ровно ×7.3 на вкладе этого шлюза. Заметить нельзя: подпись `$`,
   размерность правдоподобная.
2. **Процент запаса при этом останется «здоровым».** `pct = sumBalance / sumGrant`: если и
   `balance`, и `granted` придут юаневыми, курс сократится и процент будет верным.
   Худший вид ошибки — зелёный индикатор поверх неверного абсолютного числа.
3. **Строка провайдера** соврёт вместе с шапкой при `sym: '$'`, либо покажет `¥` рядом с
   долларовой суммой в шапке — диссонанс без объяснения.
4. **Порог годности авторотации $2 сдвинется в 7.3 раза** (`transparent-proxy.js:18981`,
   `cand.balance < Math.max(moneyMinBal(p), need)`): аккаунт с ¥2 ≈ $0.27 пройдёт как
   годный, подмена уедет на пустой ключ, запросы упадут. Это уже не косметика.
5. **Сортировка таблиц** по `balance` перемешает юаневые и долларовые строки.

Ровно этот список и есть причина, по которой 05.09 для HCNsec выбрали
«доллар канон, юань добавочным полем».

## 3. Статуслайн — где рисуется запас и есть ли там валюта

**Файл:** `routing/statusline-autoreger.sh`.

- **`gauge_from_balance_cache()`** — строка **326**. Один gauge на все денежные шлюзы.
- **Диспетчер по провайдеру** — строки **487–509**, по одной `elif`-ветке на шлюз:

- **Рендер строки** — **597**.

### Что читает

Вырезает bash-native блок `{…}` активного ключа из JSON и достаёт **регуляркой**:

```bash
bal=0; [[ "$block" =~ \"balance\"[[:space:]]*:[[:space:]]*(-?[0-9]+(\.[0-9]+)?) ]] && bal="${BASH_REMATCH[1]}"
…
avail_sum="$bal"          # строка 362
```

Знаменатель — `granted` → `balanceAnchor` → легаси `grant+bonus+referral`.
`balanceLocal` / `currencySymbol` / `currencyRate` **не читаются вообще** — их в скрипте нет.

### Валюта

**Нет. `$` захардкожен в `printf` (597):**

```bash
printf ' %s│%s %s$%s%s%s' \
    "$SEP" "$RESET" \
    "$money_col" "$avail_sum" "$age_mark" "$RESET"
```

Это **корректно**, пока `balance` в JSON долларовый — статуслайн просто печатает
каноничную единицу. Комментарий над функцией это и фиксирует: «avail_sum = balance как
есть (дашборд уже посчитал точную цифру)».

🪤 Отдельно: арифметика в статуслайне **целочисленная bash** (`bal_i="${bal%.*}"`,
`pct=$(( bal_i * 100 / grant_i ))`). Любой вариант «конвертировать в статуслайне»
потребовал бы `awk` — то есть форк на каждый промпт в функции, которую специально
писали «0 форков». Это аргумент против варианта (в) в его буквальной формулировке.

```js
    target.balanceLocal = …; target.spentLocal = …; target.grantedLocal = …;
} else {
    for (const k of ['currency','currencySymbol','currencyRate','balanceLocal','spentLocal','grantedLocal']) delete target[k];
}
```

Два важных свойства:
1. **Нормализация двух форм имён** (`rate`/`symbol` с точной ветви против
   `currencyRate`/`currencySymbol` с прикидки) — уже сделана, иначе юани доезжали бы
   только с одной ветви и молча.
2. **Самоочистка**: админ перевёл панель в доллары → поля стираются, ¥ не залипают.

### (а) Конвертировать юани в доллары по курсу 7.3, показывать `$` как у всех

**Что на самом деле означает.** Конвертация «при чтении баланса» **уже происходит** —
`quota / quota_per_unit` даёт доллары New API, а не юани. Чтобы получить (а), надо не
добавить конвертацию, а **подавить** уже работающую валютную ветку: не дать
`statusMeta` включить `rate > 1` для этого хоста (денилист по хосту) либо не писать
`balanceLocal` в запись.

**Объём:** 1–3 строки (например, ранний `return` в `statusMeta` по списку хостов).
Плюс комментарий, почему для одного хоста поведение выключено.

**Плюсы**
- Дешевле не бывает. Все девять гейджей, шапка, статуслайн, сортировка, авторотация — не
  трогаются вообще.
- Одна единица на весь дашборд, сравнивать шлюзы между собой можно глазами.

**Минусы**
- 🔴 **Ломает сверку с панелью.** Владелец открывает ЛК, видит `¥90.08`, смотрит в
  дашборд — `$12.34`. Совпадения нет, и понять, «цифра протухла или это курс», нельзя.
  Ровно на этом 05.09 сгорел HCNsec: шлюз в вике числился как «−$2174», а на деле
  «−¥2174» = −$298. Ошибка жила незамеченной именно потому, что подпись была `$`.
- 🔴 **Курс 7.3 в формулировке варианта — фиксированный.** Сегодняшняя реализация берёт
  его из `/api/status` живьём. Прибить 7.3 — регресс относительно того, что уже есть:
  админ панели поменяет курс, и цифра разъедется молча.
- Нужен денилист по хосту — механизм, которого нет, и который потом придётся объяснять
  каждому, кто добавляет следующий шлюз.
- Расходится с уже принятым решением по HCNsec: два юаневых шлюза покажутся по-разному.

## ✅ РЕКОМЕНДАЦИЯ

**Вариант (в), в его действующей редакции: валюта в записи аккаунта, канон — доллар,
курс из `/api/status`. Валютно-специфичного кода писать не нужно вообще.**

Почему не (а): она стирает единственный способ сверить дашборд с панелью глазами и
фиксирует курс, который сейчас живой. Именно эта ошибка стоила проекту цифры «−$2174»
вместо «−$298», и повторять её вторым шлюзом — значит расписаться, что урок 05.09 не
усвоен.

Почему не (б): она не чинит авторотацию (порог $2 против юаневого `balance`), а шкалу
«Общий запас» превращает в заведомо заниженную. Правило «нерабочая/врущая цифра хуже
отсутствующей» тут срабатывает против варианта: исключённый шлюз не делает цифру
отсутствующей — он делает её неверной вниз, причём без всякой пометки.

Почему (в) и почему это дёшево: механизм написан, отлажен на живом шлюзе с теми же
`CNY`/`7.3`/`500000`, `CNY` уже в таблице символов, а включение происходит по данным
`/api/status`, а не по конфигу. Добавление wisdomsatan сводится к обычной регистрации
шлюза — той же, что для долларового.

### Что доделать (это и есть весь валютный объём работ)

Три пункта, каждый мелкий; первые два — общие с HCNsec, то есть чинятся один раз на оба
шлюза.

1. **Анкер ✏️ не знает про валюту.** `newapiSetBalanceUI` (`proxy-dashboard.html:13018`)
   печатает `Сейчас потрачено $${spent}` (**13030**) и принимает число **как доллары**;
   тултип анкера в `newapiBalanceCell` (**12971**) тоже `${sym}` = `$`. Владелец,
   читающий в панели `¥90`, впишет `90` — и получит `$90` вместо `$12.33`, ошибку ×7.3
   прямо в поле, на котором стоят `balanceDenom` и вся шкала. **~10 строк:** показать в
   промпте валюту записи, конвертировать введённое по `s.currencyRate` перед отправкой.
   Заодно `newapiSetBalanceUI` после ответа **не переносит** валютные поля в `s`
   (в отличие от `hnCheckBalance`, **16444**) — дописать те же шесть присваиваний.
2. **Сайдбар показывает `$` там, где таблица показывает `¥`.** `paintSideBalance`
   (**22573**) берёт `mp.sym`, а не `act.currencySymbol`. Цифра верная, но глазами не
   сходится ни с таблицей, ни с панелью. **~5 строк:** если у активной записи есть
   `balanceLocal` и `currencyRate > 1` — рисовать её, оставив пул в долларах с подписью.
3. **Молчаливый fallback `statusMeta`.** Не ответил `/api/status` — `rate` остаётся `1`,
   и юаневый шлюз тихо считается долларовым (занижение ×7.3, никакого следа в UI).
   **~5 строк:** для хостов, у которых валюта уже была известна, не откатываться на
   `rate: 1` молча, а помечать запись (`currencyStale`) либо возвращать прошлое значение.
   Сейчас `META_CACHE` кеширует и успех, и провал — то есть один неудачный `/api/status`
   на старте процесса «прибивает» шлюз к доллару до перезапуска.

Порядок: п.1 обязателен **до** первого клика ✏️ на юаневом аккаунте (иначе цифра уедет и
её нечем будет отличить от настоящей); п.3 — до продакшена, потому что молчаливое
занижение ×7.3 ровно то, что правило «врущая цифра хуже отсутствующей» запрещает;
п.2 — косметика, можно после.

### Чего делать НЕ надо

- **Не менять `$` на `¥` в `renderWsGauge`/`renderHnGauge`** и вообще ни в одном из девяти
  гейджей вкладок: там суммируется долларовый `balance`, и `¥` сделает подпись ложной.
- **Не ставить `sym: '¥'` в `MONEY_PROVIDERS`.** Это поле — вывеска над **суммой в
  долларах** (см. комментарий про XPeach и 🍑). `¥` там соврёт ровно в 7.3 раза.
- **Не хардкодить 7.3 нигде.** Курс — настройка чужой панели.
- **Не трогать `QUOTA_PER_UNIT_DEFAULT = 500000`.** Это fallback, а живое значение и так
  приезжает из `/api/status`.
- **Не добавлять курс в `hub-balance.js` и `statusline-autoreger.sh`.** Оба читают
  долларовый `balance` и правы; правка сломала бы то, что работает.

### Открытый вопрос, который стоит проверить живьём

Текст отказа New API по деньгам (`用户剩余额度: $0.309854, 需要预扣费额度: $0.800000`)
разбирается в `moneyRotate` как `leftUsd`/`needUsd` и сравнивается с долларовым порогом
