## П.6 — `tools/check-add-gateway.js`, почему регресс 50/51

**Файл:** `tools/check-add-gateway.js`, 443 строки. Это регресс **самого инструмента** и
спеки, не вкладок: он проверяет, что спека не разошлась с инструментом, что у каждого
шлюза прогон осмыслен, что флаги согласованы. **Сейчас: `50/51`, провален ровно один
пункт.** Подтверждено живым прогоном.

### Единственный провал — блок 6

```
✗ check работает только на чтение — найден вызов на запись: writeFileSync, mkdirSync
```

Код проверки — `tools/check-add-gateway.js:404-408`:

```js
// `check` обязан только читать: регресс гоняют на живой машине, рядом с дашбордом и
// профилями браузеров. Появится `apply` (правка) — снять это утверждение осознанно,
// вместе с шапкой файла, а не «закомментировать на минутку».
const writes = ['writeFileSync', 'appendFileSync', 'rmSync', 'unlinkSync', 'mkdirSync', 'rmdirSync']
    .filter((f) => toolSrc.includes(f));
check(writes.length === 0, `check работает только на чтение${writes.length ? ' — найден вызов на запись: ' + writes.join(', ') : ''}`);
```

Проверка грепает **весь текст** `add-gateway.js` на имена write-функций Node. С тех пор как
14.09 в инструменте появился `apply`, в файле живут `fs.writeFileSync` (бэкап и запись,
`:766, :780`) и `fs.mkdirSync` (папка бэкапа, `:753`) — грепа хватает любого упоминания,
даже не вызова.

**Это устаревший тест, а не поломка.** В коде прямо написано, что при появлении `apply`
утверждение снимается **осознанно и вместе с шапкой файла**. Ни то, ни другое не сделано:

1. сам `check` от этого не перестал быть read-only (он и правда только читает — пишет
   `apply --write`, другая команда);
2. шапка `add-gateway.js:17-19, 35` по-прежнему утверждает «`apply` не делает» и «файлы
   только читаются» (см. П.1).

**Что чинить:** либо переформулировать проверку на «read-only именно команда `check`»
(сейчас она не различает команды и грепает файл целиком), либо снять её явно по инструкции
из комментария. Правки я не вносил.
